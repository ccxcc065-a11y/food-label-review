# 工程取舍与问题复盘

这是围绕食品标签审核任务开发的个人原型。下面记录问题、决定、实现位置和验证边界；没有客户部署收益或准确率提升的虚构数字。

## 1. 没拍到，不能当作没标

**问题。** 实拍标签往往只有正面或局部。OCR 没返回配料表，可能是没拍到、模糊或解析失败，不能直接推断包装缺项。

**决定。** 字段标示状态拆为已标、未标、无法识别；适用性、证据充分性、执行状态与最终结果分别记录。未覆盖和未执行不能变成通过。

**实现。** [evidence.py](../labelreview/evidence.py)、[fact_qa.py](../labelreview/fact_qa.py)、[rule_registry.py](../labelreview/rule_registry.py)。

**公开证据。** [无语料弃权测试](../tests/test_honesty_invariants.py)验证缺少依据时不产生 pass，检查点账本不出现通过。这是公开无语料路径的验证，不足以证明所有缺图、反光和混图场景已经正确处理。

## 2. 12.5 与 125：读数和计算是两种问题

**问题。** 小数点识别失败会把 12.5 读成 125。用错误读数计算，公式正确也可能给出错误整改意见。

**决定。** 保存原图区域、原始观察、重读及人工采用记录；每种数值结论声明需要的值、单位、基准和核验依据。反算候选不能自动覆盖印刷值。

**实现。** [reread.py](../labelreview/reread.py)、[evidence_checklist.py](../labelreview/evidence_checklist.py)、[nutrition_guard.py](../labelreview/nutrition_guard.py)。同一 OCR 的多次读取可能相关，不能简单叫作独立核验。

**公开证据。** 合成图片与预置文字有七个营养项目；[分发测试](../tests/test_public_distribution.py)逐项检查值、单位、NRV 和基准。[演示输入](../demos/synthetic-ocr.json)是人工生成的观察，不是实拍 OCR 测试，不能据此报告识别准确率。真实读数冲突仍需要人工标注样本复验。

## 3. 为什么没有把整个报告交给 LLM 自由生成

**问题。** 模型可能引错条款、混淆证据方向，或把“材料待查”误认为“结论矛盾”。多调用同一个模型不能自动修正这些错误。

**决定。** 可计算部分由程序执行；AI 审核提出带证据与依据的候选，经校验和必要的人工处理后形成决定。撰稿基于决定与动作，关键事实、条款与数字由程序注入。模型调用失败必须如实显示。

**实现。** [审核契约](../agents/ai-review.md)、[撰稿契约](../agents/remediation.md)、[统一决定](../labelreview/decision_set.py)、[模型调用](../labelreview/runtime_agents.py)。

**限制。** JSON、引用 ID 和数字校验不能证明全部自然语言语义正确。AI 输入过长与超时尚未解决，连续运行验收未通过；公开 CI 不调用模型。

## 4. 一次发现：CI 全绿，公开页面仍缺文件

**问题。** 首次公开版遗漏 style.css、tokens.css 和活跃角色文件。离线规则测试通过，却不能证明用户下载后的网页和模型入口完整。

**决定。** 把可分发性单独作为验收路径：检查静态资源与角色文件；干净检出安装声明依赖；启动无 OCR、无模型的演示服务；真实请求提取和成稿接口；下载字节与 contentHash 比较。

**实现。** [资源测试](../tests/test_public_distribution.py)、[HTTP 冒烟脚本](../scripts/check_demo.py)、[CI](../.github/workflows/tests.yml)。新增脚本会故意请求 AI，验证演示服务端仍禁止调用；不会用演示冒充真实模型审核。

**验证。** [本轮记录](validation.md)。既有报告不可变不意味着未来报告永远不能修错；新审核生成新成稿，查看旧成稿不重渲染。
